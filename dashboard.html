Identificación de Registros (Sin PK Nativo)

Estrategia: Los registros se identifican por combinación de columnas (claves primarias virtuales), no por ID autoincremental. El agente forma estas claves para hacer matching entre DBF y PostgreSQL.

Ejemplo de Matching por Columnas

Clave Virtual (DBF):
2024-08-14 | FAC-001234 | CLI-500
Clave Virtual (PostgreSQL):
2024-08-14 | FAC-001234 | CLI-500
Coinciden → Comparar campos

Manejo de Duplicados

Si múltiples registros comparten la misma clave virtual pero tienen datos diferentes, el sistema los marca como "ambigüedad" para revisión manual.

Escenario detectado:
2 registros con clave: 2024-08-14|FAC-001
→ Acción: Reportar ambos, no corregir automáticamente

-- Estructura de bitácora local (SQLite)
CREATE TABLE bitacora (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    timestamp DATETIME DEFAULT CURRENT_TIMESTAMP,
    tipo VARCHAR(20),        -- 'DIFERENCIA', 'ERROR_LECTURA', 'CHECKPOINT'
    archivo_dbf VARCHAR(255),
    clave_virtual VARCHAR(255),
    campo_diferente VARCHAR(100),
    valor_dbf TEXT,
    valor_pg TEXT,
    enviado BOOLEAN DEFAULT 0  -- Para reintentos si falla red
);

Arquitectura Implementada

Agente Local

  • Lenguaje: C++17
  • Librería DBF: CodeBase-for-DBF (soporta memo fields)
  • Comunicación: gRPC + mTLS (puerto 443)
  • Bitácora: SQLite local (solo diferencias)
  • SO: Windows (Servicio) / Linux (systemd)
  • Matching: Claves primarias virtuales (columnas)

Servidor Central

  • Framework: Laravel 11 + Octane
  • Modo: Solo Lectura / Visualización
  • Cola: Redis Streams
  • Base de Datos: PostgreSQL 16 + TimescaleDB
  • Restricción: Sin escritura en producción
  • Certificados: step-ca (PKI propio)

Dashboard

  • Frontend: Livewire + Alpine.js
  • CSS: Tailwind CSS
  • Gráficos: Chart.js
  • Autenticación: Laravel Breeze (3 roles)
  • Actualización: WebSockets (tiempo real)
